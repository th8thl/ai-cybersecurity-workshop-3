Session 3 · Concepts

Why a business assistant needs RAG

RAG is a key part of building useful business AI: it connects a general model to the organization’s own knowledge at answer time.

The model alone

Training does not give it reliable access to your current policies, private support documents or each employee’s permissions.

Retrieve, then answer

Fetch relevant, permitted passages from a maintained knowledge base. Give those passages to the model with the question and request source citations.

Companies use this pattern for internal knowledge assistants and customer support: answers can draw on changing business documents without retraining the model for every update.

Freshness, permissions and evidence still need application checks. Retrieval can return irrelevant, outdated or poisoned text.

Session 3 · Concepts

Keyword search compares the words you typed

What our code does

Lowercase text, split into alphanumeric tokens, remove common words, then count query terms present on each imported PDF page.

password reset → {password, reset}

Example

“Password reset support” matches both terms.

“Recover access using your credentials” matches neither term, even when it concerns the same problem.

Useful for exact terms, identifiers and known wording. This workshop uses token overlap, rather than exact phrase matching or a production full-text ranking algorithm.

Session 3 · Concepts

Semantic search compares represented meaning

Embed both sides

Turn the question and each document passage into vectors using the same embedding model. Rank passages by vector similarity.

Different words, related meaning

“I forgot my password” may retrieve account-recovery guidance even if the passage uses “credentials” or “recover access.”

The embedding model learns patterns of language. Similar vectors suggest related text; they do not prove that a passage answers the question.

Keyword search helps preserve exact wording. Semantic search helps with paraphrases. They can be combined in hybrid search; the workshop compares them separately.

Session 3 · Concepts

A vector is an ordered list of numbers

A two-dimensional example

v = [3, 4]
length(v) = √(3² + 4²) = 5
u = [6, 8] = 2v

Each position is a coordinate. These two arrows have different lengths but point in the same direction.

See the coordinates

This is a teaching example in 2D. Our actual text embeddings have 768 coordinates, without human-readable labels on individual axes.

Session 3 · Concepts

Cosine compares the direction of vectors

cosine similarity(a, b) = (a · b) / (length(a) × length(b))
a · b = a₁b₁ + a₂b₂ + … + aₙbₙ

Using the 2D example

[3, 4] · [6, 8] = 50

50 / (5 × 10) = 1: same direction.

[1, 0] and [0, 1] have similarity 0: perpendicular.

Our search uses distance

Chroma cosine distance = 1 − cosine similarity.

Lower distance means more similar. The inspect_embedding command prints similarity, where higher means more similar.

Compare all 768 coordinates. A similarity of 0.8 does not mean an 80% probability of correctness. Keyword scores and vector distances have different meanings.

Session 3 · Concepts

Embeddings turn text into comparable vectors

Embedding · the output

A numerical representation of a word, sentence or passage. The whole vector represents learned language relationships.

Individual coordinates do not mean “password,” “safe,” or “true.” Negative values are ordinary coordinates.

Embedding model · the encoder

embeddinggemma:300m, served locally by Ollama’s /api/embed, produces 768-dimensional vectors in this workshop.

The same model embeds the source chunks and the question. Changing it requires reindexing the corpus.

Qwen (qwen3:0.6b-q4_K_M) is the separate answer model. NeMo checks runtime boundaries. The explicit demo embedding fixture is hand-coded, not a learned semantic model.

Session 3 · Concepts

Chroma stores and searches the vector index

Vector database

Stores embeddings with record IDs and metadata. Given a query vector, finds nearby vectors according to a chosen distance metric.

Our workshop uses Chroma: a local persistent index with cosine distance, accessed through a short-lived worker process.

SQLite remains authoritative

Chroma returns candidate passage IDs and metadata. Django reads the passage text and current ownership, approval and revision from SQLite, then rechecks the source.

Vector proximity never grants access to a private document.

Model-specific collections keep embedding spaces separate. Update the index after changing source documents or the embedding model. No separate Chroma network server is required.
